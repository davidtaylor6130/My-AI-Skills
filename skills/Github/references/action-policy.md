# GitHub action policy

Automatic skill selection and a request to prepare work never authorise publication. David must see
and explicitly approve the concrete result before anything is sent to or changed on a remote.

## Local preparation

Proceed with relevant read-only inspection, reversible local edits, tests and isolated local work
within the requested scope. Preserve unrelated changes. Use the
[commit workflow](https://raw.githubusercontent.com/davidtaylor6130/My-AI-Skills/main/skills/Github/references/commits.md)
for local commits; a standing no-commit instruction takes precedence. Destructive or difficult-to-undo
local actions need an explicitly reviewed plan and approval too.

## Remote approval

Prepare the exact artifact, show the destination and proposed effects, and obtain David's explicit
approval before the write. This includes pushes, attachment uploads, issue/PR creation or edits,
comments/reviews, label changes, metadata/settings changes, branch/tag writes, merges and releases.
A private draft, an attachment in an unsubmitted browser form and a remote operation that can later
be deleted still count as remote writes. Do not treat "reversible on GitHub" as an exemption.

Approval may cover a concrete, enumerated batch and its exact payloads. Reuse that recorded approval
for the same action; do not repeatedly ask for unchanged approved work. Material changes to content,
scope, destination, files or effects require renewed review. A generic goal, "fix this", "open a PR"
or an old approved template is not approval of a new unseen artifact. Approval for one stage does
not authorise later merges, publication or acceptance.

Approval does not complete a missing required review. Apply [the review workflow](https://raw.githubusercontent.com/davidtaylor6130/My-AI-Skills/main/skills/Github/references/review-workflow.md)'s publication
gate, including its wait/resume rules, before approved publication or merge actions.

Finish all authorised preparation and validation before asking for approval. State what is ready,
what remains unverified and which exact remote action is proposed. If approval is denied or absent,
keep the local draft and report the unperformed action. Do not interpret silence as consent.

Keep credentials out of commands and artifacts. Read-only remote inspection is allowed when needed;
inspect command semantics so implicit pushes, uploads or state changes do not bypass this policy.

## GitHub writing

For GitHub descriptions, read [the shared writing guide](https://raw.githubusercontent.com/davidtaylor6130/My-AI-Skills/main/skills/Github/references/writing-guide.md) and the applicable
[PR](https://raw.githubusercontent.com/davidtaylor6130/My-AI-Skills/main/skills/Github/references/pr-format.md), [issue](https://raw.githubusercontent.com/davidtaylor6130/My-AI-Skills/main/skills/Github/references/issue-format.md) or [release](https://raw.githubusercontent.com/davidtaylor6130/My-AI-Skills/main/skills/Github/references/release-format.md) format. These govern
prose, evidence, review and factual model/app/harness attribution; they do not authorise publication.
